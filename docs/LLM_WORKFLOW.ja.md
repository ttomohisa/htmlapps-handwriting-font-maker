# LLMでアプリを作る手順

## 推奨プロンプト

リポジトリをLLMへ渡し、次のように指示します。

> 最初に `AGENTS.md` を全文読み、その後 `APP_SPEC.md` と `docs/ARCHITECTURE.md` を読んでください。確認ダイアログ、Undoトースト、コンパクトメニュー、数値設定、非同期状態、スマホ固定操作バー、手動WebRTC QR接続など共通UIを作り直す前に `components/` も確認してください。仕様に記載されたアプリを最後まで実装してください。単一HTML・ローカル処理を維持し、実行時CDN/API/テレメトリは追加しないでください。APP_SPEC.mdでP2P WebRTCが明示されている場合だけ、`iceServers: []` の標準QR接続部品を再利用してください。必要に応じてソース、設定、ライセンス表記、日英README、変更履歴、検証処理を更新してください。完了報告前にビルドと検証を実行してください。`dist/index.html` と `dist/index.self-extract.html` は直接編集しないでください。

## 基本の進め方

1. `APP_SPEC.md` を新しいアプリの具体的な仕様へ書き換えます。
2. `components/` を確認し、使える汎用UI部品があれば再利用します。
3. `app.config.json` の名前、slug、バージョン、説明を変更します。
4. LLMにはサンプルをすぐ削除させず、まず現在の構成を確認させます。
5. 外部ライブラリが本当に必要な場合だけ、固定バージョンで `dependencies.json` へ追加させ、`dependencies.lock.json` も同期させます。
6. 依存更新では `scripts/update-dependency.ps1` を使わせます。週次Issueは通知であり、自動更新の許可ではありません。
7. 実装のまとまりごとにビルドさせます。
8. `dist/dependency-manifest.json` と `dist/build-size-report.json` を確認し、想定外の依存・asset・容量増加がないか確認します。
9. 生成された2種類のHTMLを直接開き、主要操作を確認します。
10. 実行時通信がないことを確認してから公開します。

## LLMへ渡すと精度が上がる情報

- 入力例と上限サイズ
- 出力形式、既定ファイル名、ユーザーが編集できるファイル名、拡張子規則
- 破壊的操作とUndoの範囲
- スマートフォンのジェスチャーとスクロール挙動、プレビューとシーク/範囲操作の近接配置
- `empty / ready / loading-runtime / processing / result / error` など明示的な状態と、入力変更時の古い非同期結果の破棄
- 保存先、復元、初期化のルール
- アクセシビリティ要件
- 対象ブラウザーと端末
- 見た目が重要な場合の参考画像

## LLMにさせないこと

- 実行時サーバーが必要なフレームワークへの置換
- 一時的なCDN参照の追加
- 分析タグ、外部フォント、トラッキング、無断の更新確認
- Worker、WASM、フォント、辞書だけを外部に残した状態での「完全オフライン」表記
- 外部ライブラリの圧縮済みコードをソースへ直接貼り付けること
- 動かないボタンで未実装を隠すこと
- `dist/index.html` または `dist/index.self-extract.html` の直接編集

## 確認しやすい区切り

- 状態モデルの実装完了
- PCで主要操作が完了
- タッチ操作と狭い画面への対応完了
- 入出力処理の完了
- 依存関係とライセンスの確定
- ビルドと通信遮断検証の完了
